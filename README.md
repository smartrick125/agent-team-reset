# agent-team-reset

按成员职责更新 AI 聊天。当天任务成员收口后保存交接、归档并换新；长期成员继续保留，达到设定的对话量后再换新。

角色数量、名字和当天成员由项目配置决定。适合持续多天、分角色协作的任务。新聊天按需读取交接和文件，不复制整段旧对话。

## 安装

将 `skills/agent-team-reset` 文件夹复制到 Codex 的 `~/.codex/skills/`。也可放入支持 `SKILL.md` 的其他代理工具的技能目录。重新打开聊天后，使用 `$agent-team-reset`，或明确提出全组收口、全组开工。

技能需要宿主提供聊天管理工具。Codex 与 Claude 的聊天管理能力各自独立，安装技能不会增加宿主本来没有的权限或工具。

## 配置

把 `skills/agent-team-reset/references/team.json` 复制到自己的项目并命名为 `team.json`，按实际分工修改。`handoff` 是相对配置文件所在目录的路径。真实聊天编号只保存在本地状态中。

让协调角色执行技能。只有协调角色写状态，每个成员只写自己的交接。使用口令前明确要管理的项目和成员，避免操作无关聊天。

每个成员必须配置 `lifecycle`。`task` 用于当天学习指导等独立任务，任务结束后换新。`persistent` 用于宣发、推广等持续职责，跨天保留原聊天。下一天可以增加、删除或更换任务成员，仍在工作的长期成员不会被一起归档。

长期成员通过 `persistent_class` 分类：维护常驻 `maintenance` 在 30 个用户回合后换新，普通常驻 `regular` 在 20 个用户回合后换新。达到阈值后，在任务安全停点先交接再归档。一次用户发言算一回合，助手回复和工具调用不计入。回合数不是 token 用量。旧配置的显式阈值保持不变，迁移须执行 `policy`。

## 使用

1. 说“全组收口”。协调者先执行 `close-team` 记录关闭意图，再让全员保存交接、封存并通过宿主归档。关闭期间不会生成补员计划。只结束当天任务时，使用单独的 `close-plan` 流程，保留未到阈值的长期成员。
2. 说“全组开工”。协调者核对已有聊天，只建立配置中缺少的成员。新成员读取自己的封存交接并确认接手未完任务。
3. 要维护长期成员时，要求“检查长期成员对话量”。协调者用 `count` 读取已配置的本机日志，或用核对过的累计数执行 `observe`，再用 `maintenance-plan` 筛选达标成员。交接、归档完成后用 `renew` 准备该角色换新。

宿主读不到完整对话轮数时，会报告限制，不会凭聊天摘要估算。达到阈值后在安全停手点换新，不中断正在做的任务。

如果宿主不提供归档或新建工具，技能会保留交接并说明需要手动完成的动作。归档不等于删除消息，也不会清空当前打开的聊天框。本项目没有后台监控服务，不承诺固定的 token 节省比例。

## 检查本地状态

需要 Python 3.10 或更新版本，无第三方运行依赖。

```sh
python skills/agent-team-reset/scripts/rotate.py --config team.json --state .team-reset/state.json --host codex begin demo-1
python skills/agent-team-reset/scripts/rotate.py --config team.json --state .team-reset/state.json --host codex open-plan demo-1
python -m unittest discover -s tests -v
```

脚本输出操作计划和维护恢复状态。真实聊天操作由代理通过宿主工具执行，脚本不能验证宿主回执是否真实。离线测试覆盖状态约束，不能替代真实宿主集成测试。

不要把真实交接、聊天编号或本地状态上传到公共仓库。示例均为虚构角色。许可证为 MIT。

## 自动计数与整组移交

配置 `transcripts` 后，`count` 从本机聊天记录统计用户消息。Claude 按消息 ID 去重；Codex 只统计来源元数据含 `user.text` 的消息，排除任务转发和执行启动。记录不完整时报告未知，不猜测。无法自动读取时，用核对过的累计数执行 `observe`。

配置 `roster` 后，每次状态保存都会更新成员构成表。批次历史默认保留 10 批，退役聊天编号保留 50 个，交接超过默认 80 行时拒绝封存。

说“全组移交”可在平台之间交接整个团队。协调者执行 `handover-plan`，确认全员交接并通过宿主归档，最后执行 `handed-over --to NEW_HOST`。旧状态随即锁定，新平台使用独立状态文件重建团队。实际聊天操作依赖宿主工具与用户授权。

## 检查缺员与继承交接

运行 `check --refresh-counts` 只读刷新本机日志计数，不写共享状态。协调者用 `count` 保存经过核对的计数。来源未知或新读数低于已存值时，先审计，不自动归档。

配置名册决定预期成员。`running` 模式下，脚本为真正缺员生成补员计划；宿主状态不确定时先核对，不重复建人。`closing` 和 `closed` 模式不会补员。检查需明确执行，本项目不安装后台监控。

换新前，把未完任务、决定和下一步写进角色专用的 `handoffs/` 文件并封存。新成员读完后，用实际新聊天 ID 和封存哈希登记 `read-receipt`。已读表示接手，不能代替完成任务。

`cleanup` 默认预览。获准后执行 `cleanup --apply`，只删除已确认读取且内容未变的专用交接文件，保留报告、未读取内容和链接目标。实际创建、消息和归档仍由宿主工具执行。
